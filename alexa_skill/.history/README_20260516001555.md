# Skill de Alexa — Cine Inteligente

Práctica de IA Agéntica · Agentes Inteligentes

---

## Descripción

Skill de Amazon Alexa que permite consultar información de películas por voz.
El usuario puede preguntar por la nota, número de votos, sinopsis, director,
duración y género de cualquier película, usando lenguaje natural en español.

Los datos se obtienen de la API de **OMDb** (Open Movie Database) y se cachean
en memoria para no repetir consultas innecesarias, tal y como pide el enunciado.

## Cómo ejecutar el scraper por línea de comandos

El archivo `imdb_scraper.py` cumple el requisito de ser ejecutable directamente:

```bash
# Instalar dependencias
pip install -r requirements.txt

# Consultar una película (con OMDB_API_KEY configurada)
export OMDB_API_KEY=tu_api_key_aqui

python imdb_scraper.py "Inception"
python imdb_scraper.py "El Padrino"
python imdb_scraper.py "2001 Odisea en el Espacio"
```

Salida de ejemplo para "Inception":
```json
{
  "titulo": "Inception",
  "anio": "2010",
  "nota": "8.8",
  "votos": "2.6 millones",
  "sinopsis": "A thief who steals corporate secrets...",
  "director": "Christopher Nolan",
  "duracion": "148 min",
  "generos": "Action, Adventure, Sci-Fi",
  "imdb_url": "https://www.imdb.com/title/tt1375666/"
}
```

> **Nota:** para obtener una API key gratuita de OMDb:
> https://www.omdbapi.com/apikey.aspx (plan gratuito: 1000 peticiones/día)

## Cómo desplegar en AWS Lambda

### 1. Generar el ZIP de despliegue

```bash
cd alexa_skill_def
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
bash deploy_lambda.sh
```

Esto genera `lambda_package.zip`.

### 2. Configurar AWS Lambda

- **Runtime:** Python 3.11
- **Handler:** `lambda_function.handler`
- **Memoria:** 512 MB
- **Timeout:** 20 segundos
- **Trigger:** Kit de habilidades de Alexa

Sube el ZIP en: `Code → Upload from → .zip file`

Variables de entorno:
```
OMDB_API_KEY = tu_api_key_real
USE_DYNAMO   = false
CACHE_TTL_DAYS = 7
```

### 3. Configurar Alexa Developer Console

1. Crear skill con nombre de invocación: `cine inteligente`
2. Locale: Spanish (ES)
3. `Build → Interaction Model → JSON Editor` → pegar `interactionModel.json`
4. `Build → Endpoint` → seleccionar AWS Lambda ARN → pegar el ARN de la función

## Diseño de la caché

La caché evita llamadas repetidas a OMDb para la misma película:

```
Primera consulta:
  Usuario pregunta por "Inception"
  → cache.get_cached("Inception") → None
  → imdb_scraper.get_movie_info("Inception") → llama a OMDb
  → cache.set_cached("Inception", datos)

Segunda consulta (misma sesión u otra):
  Usuario pregunta por "Inception"
  → cache.get_cached("Inception") → datos ✓ (sin llamar a OMDb)
```

La normalización de claves permite que "El Padrino", "el padrino" y
"padrino" apunten a la misma entrada en caché.

## Decisiones de diseño

**¿Por qué OMDb en lugar de scraping directo de IMDb?**
IMDb bloquea activamente el scraping automatizado. OMDb es una API oficial
que agrega los mismos datos de forma estable y con licencia de uso.

**¿Por qué dos niveles de caché?**
La caché en memoria es suficiente para la práctica (el contenedor de Lambda
puede permanecer caliente varios minutos). DynamoDB sería necesario en
producción para persistir entre invocaciones frías.

**¿Por qué `SESSION_KEY` en la sesión de Alexa?**
Permite conversaciones multi-turno: el usuario puede preguntar
"cuánto dura" sin repetir el título si ya lo mencionó antes en la misma sesión.
